# 마음모아 · Samsung Card

삼성카드 임직원을 위한 칭찬 문화 플랫폼의 반응형 웹 프로토타입입니다.

## 실행

Node.js 20.19+ 또는 22.12+ 권장 (개발 환경: Node.js 24).

```sh
npm ci
npm run dev -- --port 5173
```

## 화면과 기능

- **홈**: 로그인 후 `#home`에서 짧은 플랫폼 소개, 칭찬 보내기 바로가기와 전체 칭찬 중 최대 12장이 왼쪽으로 흐르는 배너를 보여줍니다.

- **로그인**: 마음mo아 랜딩 화면, ID/PW 입력, 임의 사번/PW로 가상 계정 생성, 로그인 세션 유지 및 로그아웃.
- **칭찬 보내기**: ① 받는 동료 → ② 칭찬 유형·메시지 → ③ 카드 선택 → ④ 미리보기의 네 화면을 다음/이전으로 이동합니다. 입력을 검증하고 단계 전환 시 페이드 아웃·페이드 인을 적용하며, 이전 단계로 돌아가도 작성 내용이 유지됩니다.
- **랜덤 칭찬 배너**: `/#home`에서 전체 칭찬 중 최대 12장을 무작위로 골라 왼쪽으로 반복 표시합니다. 일시정지/재생, 마우스 올리기·키보드 포커스 시 정지, 카드 클릭 시 전문 보기를 지원합니다. 모션 줄이기 설정에서는 자동 이동 대신 수동 가로 스크롤을 제공합니다.
- **마이페이지**: 받은 칭찬/보낸 칭찬/젤리 내역, 유형별 필터, 칭찬 수와 온도, 젤리 보유량.
- **임직원 프로필**: 이름·부서 검색, 상세/일정/칭찬 탭, 칭찬 온도계, 공개 칭찬 이력, 해당 동료에게 칭찬 보내기.
- 모바일 대응, 로컬 한글 웹폰트, 키보드 포커스 및 대화상자 포커스 제한.

처음 방문하면 로그인 화면이 표시됩니다. 비어 있지 않은 임의 사번과 비밀번호로 체험할 수 있습니다. 비밀번호를 검증하거나 저장하지 않는 데모용 진입 화면으로 실제 사내 인증과 연결되지 않습니다. 사번은 앞뒤 공백과 영문 대소문자를 정규화한 SHA-256 해시로 식별하며 원문은 저장하지 않습니다.

최초 로그인 시 랜덤 동물 이름(예: 개구진 악어, 졸린 사자)을 만들고 부서는 **삼성카드 아이디어톤팀**으로 고정합니다. 같은 브라우저에서 같은 사번으로 재접속하면 비밀번호와 관계없이 같은 이름과 이력이 복원됩니다. 브라우저 데이터 삭제, 시크릿 창 종료 또는 다른 기기로 이동하면 이력이 이어지지 않습니다.

계정은 localStorage의 `maeum-accounts-v2`, 칭찬은 `maeum-praises-v2`, 현재 로그인 계정 ID는 sessionStorage의 `maeum-session-v2`에 보관합니다. 기존 `maeum-praises`와 `maeum-demo-session`은 이번 버전 접속 시 제거하며 과거 버전의 칭찬은 불러오지 않습니다. 요청된 12명에게 예시 칭찬 한 개씩을 제공하며, `maeum-welcome-samples-v1` 마커로 최초 한 번만 추가합니다. 기존 v2 이력과 가상 계정은 보존하고, 예시 카드 ID로 중복을 방지합니다. 이후 새로 작성한 칭찬은 재접속해도 지우지 않습니다. 계정별 받은/보낸 이력과 젤리는 각자의 ID로 계산합니다. 가상 계정은 발신자 이름과 본인의 이력 표시에만 사용하며 칭찬 수신자로 검색하거나 선택할 수 없습니다.

로그인 전 흰 화면 가운데 ‘마음 아’가 나타나고, 사이의 MO가 자라나 로고를 완성합니다. 완성된 로고가 로그인 화면 왼쪽 위로 이동하면 랜딩 화면이 서서히 나타납니다. 인트로는 페이지 로드당 한 번 실행하며 로그아웃 때 반복하지 않습니다. 모션 줄이기 설정에서는 인트로와 단계 전환 애니메이션을 생략합니다.

### 젤리와 칭찬 온도

칭찬 한 장당 수신자의 **데모 스페셜 젤리 1개**와 **온도 0.3°C**가 추가됩니다(최대 60°C). 받은 칭찬 수는 저장된 전체 수신 이력 개수, 스페셜 젤리 잔액은 그 개수, 온도는 36.5°C + 그 개수 × 0.3°C로 계산합니다. 별도 가산 잔액은 없습니다. 새 가상 계정은 받은 칭찬 0개, 스페셜 젤리 0개, 온도 36.5°C로 시작합니다. 지정된 12명은 예시 칭찬 1개와 온도 36.8°C로 시작하며, 이후 받은 칭찬을 합산합니다. **실제 모니모 앱과 연동되지 않으며 금전적 보상은 지급하지 않습니다.**

캐릭터는 제공된 이미지를 참고해 SVG로 그린 웹용 시안입니다. 실제 서비스 사용 전 공식 브랜드 자산으로 교체할 수 있습니다.

## 검증

```sh
npm test
npm run build
# 테스트가 필요한 개발 서버를 자동으로 시작합니다.
npm run test:e2e
```

브라우저 테스트는 `/usr/bin/chromium`을 사용합니다. 다른 환경에서는 `playwright.config.js`의 `executablePath`를 해당 Chromium 경로로 지정하거나 제거하고 `npx playwright install chromium`을 실행하세요.

검색·입력 검증, 카드 미리보기, 전송, 새로고침 후 저장 유지, 프로필 칭찬 수/온도 갱신, 받은 칭찬에 따른 젤리 잔액 갱신, 모바일 가로 넘침을 확인합니다.

## 실서비스 연결 시 필요한 작업

사내 SSO 인증, 실제 조직도 조회, 서버 기반 칭찬 저장·공개 정책 및 권한 검사, 모니모 리워드 지급 API 연동이 필요합니다. 중복 지급 방지와 지급 실패 처리, 칭찬 노출/개인정보 정책도 서버에서 구현해야 합니다. 현재 일정 탭은 연동 전 빈 상태를 안내합니다.

## 시연 링크 공유 · GitHub Pages

사이트의 배포 결과물은 **`gh-pages` 브랜치**에 있습니다. 실제 직원 데이터와 외부 서비스 연결 없이 가상 데이터로 체험하는 정적 웹사이트입니다.

최초 한 번, 저장소 관리자가 GitHub에서 다음을 설정해주세요.

1. 저장소 **Settings → Pages**로 이동합니다.
2. **Build and deployment → Source**에서 **Deploy from a branch**를 선택합니다.
3. **Branch**를 **gh-pages**, 폴더를 **/docs**로 선택하고 **Save**합니다. (`/ (root)` 경로도 지원합니다.)
4. Pages 화면에 표시되는 배포 완료 URL을 공유합니다. 기본 예상 주소는 `https://heestogram.github.io/monimo/`입니다. 실제 활성화·배포 완료 후 사용할 수 있습니다.

`main`은 원본 코드, `gh-pages`는 빌드된 사이트를 보관합니다. `main` 수정만으로 배포 파일이 갱신되지는 않습니다. 디자인을 수정한 경우 `npm ci && npm run build`로 다시 빌드해 `gh-pages`에 반영해야 합니다.

Vite의 상대 경로 설정으로 GitHub Pages의 `/monimo/` 하위 경로에서도 CSS·JavaScript·폰트가 로드됩니다. 각 방문자의 칭찬은 해당 브라우저에만 저장되므로 다른 방문자와 데이터를 공유하지 않습니다.

Vercel을 사용하는 경우 GitHub 저장소를 Import하고 Framework Preset **Vite**, Build Command **npm run build**, Output Directory **dist**로 배포할 수도 있습니다. 별도의 비밀키나 환경 변수는 필요하지 않습니다.

## 모바일 사용 및 QR 공유

휴대폰에서는 화면 하단의 메뉴로 칭찬 보내기·마이페이지·임직원 프로필을 이동합니다. 칭찬 작성은 모바일에서도 동일한 4단계 화면으로 진행하며, 각 단계 아래의 다음/이전 버튼으로 이동합니다. 마지막 단계에서 전송하며, 입력창에 포커스가 있는 동안 하단 메뉴를 숨겨 키보드 입력 공간을 확보합니다. 입력 글자 크기는 모바일에서 16px로 설정했습니다.

QR코드는 로그인 첫 화면 `https://heestogram.github.io/monimo/`로 연결됩니다.

- 화면 공유용 PNG: `public/share/maeum-moa-qr.png` (540 × 540px)
- 확대·인쇄용 SVG: `public/share/maeum-moa-qr.svg`
- 배포 후 다운로드 경로: `https://heestogram.github.io/monimo/share/maeum-moa-qr.png`

원하는 체험용 사번과 비밀번호로 로그인할 수 있습니다. QR코드에는 접속 주소만 들어 있으며 로그인 정보는 포함하지 않습니다.

마이페이지의 받은 칭찬·온도·젤리 요약 카드는 표시하지 않으며, 칭찬 이력 탭과 스페셜 젤리 내역 탭은 유지합니다. 전체 직원 목록에서 본인은 표시되지만 수신자로 선택할 수 없습니다.

직원 검색과 전체 임직원 선택, 포탈 동료 검색에는 요청된 12명만 표시합니다. 새 로그인으로 생성된 가상 계정은 목록에 추가하지 않습니다.
